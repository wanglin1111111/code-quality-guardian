# 代码审查标准 Checklist

## 安全性检查

### 输入验证
- [ ] 所有外部输入（用户输入、API 参数、文件上传）都经过验证和清洗
- [ ] 使用参数化查询或 ORM，无 SQL 注入风险
- [ ] 文件路径经过规范化处理，无路径遍历漏洞
- [ ] 文件大小和类型校验到位

### 认证与授权
- [ ] 所有敏感操作都有服务端权限校验
- [ ] Session/Token 有过期机制
- [ ] 密码使用强哈希算法（bcrypt / Argon2）
- [ ] API 端点有速率限制

### 加密与密钥
- [ ] 无硬编码的密码、密钥、Token
- [ ] 敏感数据加密存储和传输
- [ ] 使用安全随机数生成器（secrets / os.urandom）
- [ ] TLS 证书验证已启用

### 注入防护
- [ ] 无 eval() / exec() 调用
- [ ] 无 shell=True 的 subprocess 调用
- [ ] 模板引擎输出已转义（防 XSS）
- [ ] 无 OS 命令拼接

## 正确性检查

### 错误处理
- [ ] 所有可能失败的 IO 操作都有 try-except
- [ ] 异常被正确分类和处理，无裸 except
- [ ] 错误信息不泄露敏感信息
- [ ] 资源（文件、连接、锁）正确释放

### 边界条件
- [ ] 空值/None 检查到位
- [ ] 数组/列表边界检查
- [ ] 递归有终止条件
- [ ] 浮点数精度问题已处理

### 并发安全
- [ ] 共享资源访问有锁保护
- [ ] 无死锁风险（锁顺序一致）
- [ ] 异步操作有错误回调
- [ ] 线程安全的数据结构

## 可维护性检查

### 代码结构
- [ ] 单一函数 < 50 行
- [ ] 单一函数圈复杂度 < 10
- [ ] 嵌套深度 < 4 层
- [ ] 无重复代码（DRY 原则）

### 命名规范
- [ ] 变量名清晰表达意图
- [ ] 函数名使用动词开头
- [ ] 类名使用大驼峰
- [ ] 常量使用大写下划线

### 注释与文档
- [ ] 公共函数有 docstring
- [ ] 复杂逻辑有行内注释
- [ ] 公共 API 有使用示例
- [ ] README 保持更新

## 性能检查

### 数据库
- [ ] 无 N+1 查询
- [ ] 批量操作替代单条循环
- [ ] 索引策略合理
- [ ] 连接池配置正确

### 缓存
- [ ] 热点数据有缓存
- [ ] 缓存 key 设计合理
- [ ] 缓存失效策略明确
- [ ] 无缓存雪崩/击穿风险

### 算法
- [ ] 时间复杂度可接受
- [ ] 无不必要的重复计算
- [ ] 大数据集使用流式处理
- [ ] 内存使用合理

## 测试覆盖

- [ ] 核心逻辑有单元测试
- [ ] 边界条件有测试用例
- [ ] 异常场景有测试
- [ ] 集成测试覆盖关键路径
- [ ] 测试代码本身可维护
